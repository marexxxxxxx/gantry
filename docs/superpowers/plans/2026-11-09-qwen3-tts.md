# Qwen3-TTS GPU TTS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Qwen3-TTS-12Hz-1.7B-CustomVoice lokal installieren und über `POST /v1/audio/speech` mit `"model": "Qwen3-TTS"` verfügbar machen; das Modell läuft nur auf der GPU, nachdem der Chat entladen wurde.

**Architecture:** Ein eigener FastAPI-Worker `aiserver_qwen_tts` auf Port 30005 hält das Modell lazy auf `cuda:0`. Der bestehende Audio-Sidecar auf 30003 bekommt einen HTTP-Client und leitet Qwen3-TTS-Anfragen weiter. Das Gateway nimmt `Qwen3-TTS` in den Lifecycle-Katalog auf: `/v1/load` startet den Worker und lädt das Modell, `/v1/unload` entlädt es und stoppt den Worker.

**Tech Stack:** Python 3.12, FastAPI, uvicorn, httpx, PyTorch mit CUDA 12.8, `qwen-tts==0.1.1`, unittest.

**Spec:** `docs/superpowers/specs/2026-11-09-qwen3-tts-design.md`

## Global Constraints

- Keine Commits erstellen: das Repo enthält viele uncommittete Änderungen des Nutzers. Alle Änderungen bleiben uncommittet.
- Bestehende, nicht committete Dateien nur gezielt ändern; nichts überschreiben.
- Tests sind `unittest`, nicht pytest. Aus `/home/user/small_qwen/aiserver-monitor`:
  `../.venv/bin/python -m unittest discover -s tests -p 'test_*.py'`
- Baseline vor dieser Aufgabe: 503 Tests, `OK`. Der volle Lauf muss am Ende grün bleiben.
- Kein CPU-Fallback für Qwen3-TTS. Bei VRAM-Mangel klarer Fehler.
- Modellnamen bleiben exakt: Lifecycle-Profil und `model`-String sind `Qwen3-TTS`.
- Der Standardstart von `run.sh` startet Qwen3-TTS **nicht**; nur `/v1/load` oder `run.sh start-qwen-tts`.
- Der Worker wird erst gestartet, wenn kein Chat-Backend läuft. Läuft Chat, antwortet `/v1/load` mit 409.
- `speed` wird von Qwen3-TTS derzeit ignoriert; der Wert wird angenommen, aber nicht an `generate_custom_voice` weitergegeben.

## Review Focus

- Läuft noch Chat, darf `/v1/load` mit `Qwen3-TTS` nichts starten und muss 409 liefern.
- Ein VRAM-Fehler muss als 503 mit klarer Meldung ankommen, niemals als stiller CPU-Fallback.
- `/v1/unload` muss den Worker-Prozess beenden, sonst bleibt der CUDA-Kontext belegt.
- `model: "Qwen3-TTS"` muss case-insensitiv im Audio-Sidecar erkannt werden; der Lifecycle bleibt exakt.
- Die Piper-Default-Stimme darf nicht an Qwen durchgereicht werden; sie wird zu `Vivian`.
- Fehlende Modell-Dateien müssen 503 mit dem Hinweis auf `runtime/qwen-tts/download-models.sh` liefern.
- Der Worker-Healthcheck darf `model_loaded: false` melden, ohne den Prozess als kaputt zu behandeln.

```python
        settings = QwenTTSSettings(model_dir=Path("/tmp/qwen"), device="cpu")
        return QwenTTSEngine(settings, model_loader=loader)

    def test_loads_lazily_and_only_once(self):
        model = FakeModel()
        calls = []

        def loader(_settings):
            calls.append("load")
            return model

        engine = self._engine(loader)
        self.assertFalse(engine.model_loaded)
        engine.synthesize("Hallo", speaker="Vivian", language="German")
        engine.synthesize("Nochmal", speaker="Ryan", language="German")
        self.assertTrue(engine.model_loaded)
        self.assertEqual(calls, ["load"])

    def test_synthesize_returns_int16_pcm(self):
        engine = self._engine(lambda _s: FakeModel())
        pcm, sr = engine.synthesize(
            "Guten Tag.", speaker="Vivian", language="German")
        self.assertEqual(sr, 24000)
        self.assertEqual(len(pcm), 6)
        self.assertEqual(np.frombuffer(pcm, dtype=np.int16).tolist(),

        engine.load()
        engine.unload()

            engine.load()
        self.assertEqual(ctx.exception.status_code, 503)
```

```python
class QwenTTSError(Exception):
    def __init__(self, status_code: int, code: str, message: str) -> None:
        super().__init__(message)
        self.status_code = status_code
        self.code = code
        self.message = message
```

`engine.py`:
- `_standard_loader(settings)` imports `torch` and `qwen_tts.Qwen3TTSModel` inside the function and calls:
  `Qwen3TTSModel.from_pretrained(str(settings.model_dir), device_map=settings.device, dtype=getattr(torch, settings.dtype))`
- `load()` uses a `threading.Lock`, calls the loader once, stores `self._model`.
- `synthesize()` calls `load()` if needed, then under the lock and `torch.inference_mode()`:
  `wavs, sr = model.generate_custom_voice(text=text, language=language, speaker=speaker, instruct=instruct)` (omit `instruct` when it is `None` or empty).
- Convert `wavs[0]` with `np.asarray(..., dtype=np.float32).reshape(-1)`, clip to `[-1, 1]`, multiply by 32767, cast to `int16`, return `(pcm.tobytes(), int(sr))`.
- Catch `torch.cuda.OutOfMemoryError` and `RuntimeError` whose text contains `"out of memory"`, raise `QwenTTSError(503, "vram_exhausted", "Nicht genug VRAM fuer Qwen3-TTS. Zuerst /v1/unload ausfuehren.")`.
- `unload()` sets `self._model = None`, calls `gc.collect()`, and if torch is importable calls `torch.cuda.empty_cache()`.
